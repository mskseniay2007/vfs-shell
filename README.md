# VFS Shell — эмулятор командной строки UNIX-подобной ОС

Учебный проект по дисциплине «Операционные системы» на Python. Представляет
собой эмулятор командной оболочки с виртуальной файловой системой (VFS),
которая хранится в памяти и загружается из JSON-файла.

## Основные возможности

- Интерактивный режим (REPL) — как в настоящем терминале.
- Параметры командной строки: `--vfs` (путь к JSON-файлу VFS) и `--script`
  (путь к стартовому скрипту).
- Отладочный вывод всех параметров при запуске.
- Выполнение стартовых скриптов с поддержкой комментариев (`#`).
- Виртуальная файловая система, полностью хранящаяся в памяти.
- Вывод файла `motd` при старте, если он есть в корне VFS.
- Набор команд: `ls`, `cd`, `uname`, `uniq`, `touch`, `mkdir`, `exit`.
- Все изменения VFS — только в памяти. Файл `vfs.json` на диске не
  изменяется.
- Обработка ошибок: несуществующие пути, файлы, каталоги, отсутствие
  аргументов.

## Требования

- Python 3.10 или выше.
- macOS или Linux — для запуска `.sh`-скриптов.

## Установка и запуск

```bash
git clone https://github.com/mskseniay2007/vfs-shell.git
cd vfs-shell
```

### Создание виртуального окружения (по желанию)

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Запуск эмулятора

Интерактивный режим:

```bash
python main.py --vfs vfs.json
```

Выполнение стартового скрипта:

```bash
python main.py --vfs vfs.json --script start.txt
```

Проверка обработки ошибок (несуществующий скрипт):

```bash
python main.py --vfs vfs.json --script несуществующий.txt
```

## Параметры командной строки

| Параметр | Обязательный | Описание |
|---|---|---|
| `--vfs` | Да | Путь к JSON-файлу виртуальной файловой системы |
| `--script` | Нет | Путь к файлу со стартовым скриптом |

При запуске программа выводит отладочную информацию обо всех переданных
параметрах:

```
[DEBUG] VFS: vfs.json
[DEBUG] Скрипт: start.txt
```

## Формат VFS

Виртуальная файловая система описывается JSON-файлом. Структура —
вложенная: папки содержат `children`, файлы — `content`.

Файл:

```json
{
  "name": "readme.txt",
  "type": "file",
  "content": "текст внутри файла"
}
```

Папка:

```json
{
  "name": "home",
  "type": "dir",
  "children": []
}
```

Корень VFS:

```json
{
  "name": "/",
  "type": "dir",
  "children": [
    {"name": "motd", "type": "file", "content": "Добро пожаловать!"},
    {"name": "home", "type": "dir", "children": []}
  ]
}
```

Поля:

- `name` — имя файла или папки.
- `type` — `"file"` для файлов, `"dir"` для папок.
- `content` — содержимое файла (только у файлов).
- `children` — список содержимого папки (только у папок).

Если в корне VFS есть файл `motd`, его содержимое автоматически
печатается при запуске эмулятора.

## Поддерживаемые команды

| Команда | Описание |
|---|---|
| `ls [путь]` | Выводит содержимое каталога. Папки помечаются `/` на конце |
| `cd <путь>` | Меняет текущий каталог |
| `uname` | Печатает имя системы: `VFS-Shell 1.0` |
| `uniq <файл>` | Удаляет подряд идущие дубликаты строк в файле |
| `touch <файл>` | Создаёт пустой файл (только в памяти) |
| `mkdir <папка>` | Создаёт пустую папку (только в памяти) |
| `exit` | Выход из эмулятора |

## Формат стартового скрипта

Стартовый скрипт — обычный текстовый файл. Одна команда на строку.
Пустые строки и строки, начинающиеся с `#`, игнорируются.

Пример:

```
# Это комментарий — программа его пропустит

# Работа с VFS
ls
cd home
cd user
ls

# Новые команды
touch newfile.txt
mkdir newdir
ls

# Обработка ошибок
cd /nonexistent
touch /no/such/dir/file.txt

exit
```

При выполнении скрипта на экран выводится и ввод, и вывод — как если бы
пользователь вводил команды вручную.

## Скрипты реальной ОС

В проекте есть пять `.sh`-скриптов — они запускают эмулятор с разными
параметрами. Это сценарии для реальной ОС (macOS/Linux).

Перед первым запуском нужно дать файлам право на исполнение:

```bash
chmod +x run_*.sh
```

Запуск:

```bash
./run_interactive.sh   # интерактивный режим
./run_script.sh        # со стартовым скриптом
./run_error.sh         # проверка ошибки
./run_minimal.sh       # минимальный VFS
./run_deep.sh          # глубокий VFS
```

## Особенность: изменения только в памяти

Все команды, изменяющие VFS (`touch`, `mkdir`), работают с копией VFS в
оперативной памяти. Файл `vfs.json` на диске не изменяется. После выхода
из программы созданные файлы и папки исчезают, а при следующем запуске
VFS снова загружается из исходного JSON. Это соответствует требованию
задания — «модификации должны осуществляться только в памяти».

## Обработка ошибок

Программа корректно реагирует на:

- Несуществующий файл скрипта:
  ```
  Ошибка: файл скрипта 'несуществующий.txt' не найден.
  ```
- Несуществующий путь в `cd`:
  ```
  cd: /nonexistent: нет такого каталога
  ```
- Несуществующий файл в `uniq`:
  ```
  uniq: nonexistent.txt: нет такого файла
  ```
- Каталог вместо файла в `uniq`:
  ```
  uniq: /home: это каталог
  ```
- `touch` / `mkdir` без аргумента:
  ```
  touch: укажите имя файла
  mkdir: укажите имя каталога
  ```
- `mkdir` на существующее имя:
  ```
  mkdir: newdir: уже существует
  ```
- `touch` / `mkdir` в несуществующем каталоге:
  ```
  touch: /no/such/dir/file.txt: нет такого каталога
  ```
- Неизвестная команда:
  ```
  blabla: команда не найдена
  ```

## Архитектура кода

В `main.py` реализованы:

Работа с VFS:

- `load_vfs(path)` — загружает JSON в память.
- `find_child(node, name)` — ищет дочерний узел по имени.
- `get_node(root, path_list)` — возвращает узел по пути.
- `resolve_path(root, cwd, target)` — разбирает путь (`..`, `.`,
  абсолютный/относительный).
- `path_to_str(path_list)` — превращает список имён в строку `/home/user`.
- `split_parent_and_name(target, cwd)` — делит путь на родителя и имя.

Команды:

- `cmd_ls`, `cmd_cd`, `cmd_uname`, `cmd_uniq`, `cmd_touch`, `cmd_mkdir`.

Обработка ввода:

- `parse_command(line)` — разбивает строку на команду и аргументы.
- `process_line(line, state)` — диспетчер: определяет, какую команду
  выполнять.

Запуск:

- `parse_args()` — разбор параметров `--vfs`, `--script`.
- `print_motd(root)` — печать `motd`.
- `run_script(path, state)` — выполнение стартового скрипта.
- `repl(state)` — интерактивный цикл.
- `main()` — точка входа.

Всё состояние VFS хранится в словаре `state`:

- `state["root"]` — корень VFS.
- `state["cwd"]` — текущая директория (список имён от корня).
